## Reglas de uso (leer antes de escribir)

1. **Apendizar, no sobrescribir.** Cada entrada nueva va al final de su sección con la fecha absoluta (`YYYY-MM-DD`) y, cuando aplique, una referencia corta al hilo o tarea que la originó.
2. **Nunca borrar entradas históricas.** Si una decisión se revierte o un dato cambia, se añade una entrada nueva que la marca como **obsoleta** y apunta a la entrada vigente.
3. **Sin duplicar.** Antes de añadir, revisar si ya existe algo equivalente. Si sí, actualizar referenciando la entrada anterior, no duplicarla.
4. **Granularidad útil.** Una entrada por hecho/decisión, no párrafos largos. Lead con la afirmación; opcional `Por qué:` y `Cómo aplicar:`.
5. **No es para ejecución.** Tareas en curso van en TodoList o en plan, no acá. Acá solo entra lo que va a importar la próxima vez.
6. **Qué NO va acá:** secretos, tokens, credenciales, datos personales sensibles de clientes (cédulas, capturas, etc.). Para eso existen `.env` y Airtable.

(Aprendizajes técnicos detallados de Make AI Agents Beta están consolidados en `compound_review_2026-04-27.md` §1-19. Acá quedan los más críticos como recordatorio rápido.)

- **2026-04-27** — `metadata.expect` del módulo `ReturnData` es OBLIGATORIO en sub-escenarios callables.
  - Por qué: sin él, el módulo evalúa el mapper pero no emite la bundle al caller. La API devuelve `{}` y el agente recibe outputs vacíos sin warning. Costó ~media tarde de debugging la primera vez.
  - Cómo aplicar: en cada blueprint nuevo, incluir `metadata.expect` 1:1 con `interface.output`. Validar tras crear el sub-escenario corriéndolo via `scenarios_run` con `responsive: true` y verificar que la respuesta incluye `outputs: {...}`.
- **2026-04-27** — `required: true` en inputs de sub-escenarios callables ROMPE la validación cuando el valor llega vía mapper dinámico (`{{3.wa_from}}`).
  - Por qué: Make pre-valida ANTES de resolver variables; el template literal aparece como vacío.
  - Cómo aplicar: setear todos los inputs como `required: false` (en blueprint, en interface y en metadata.interface). Validar el "campo no vacío" dentro del flow con `if + ifempty + fallback`.
- **2026-04-27** — NUNCA tocar el blueprint del scenario `wa_inbound` vía API si tiene tools linkeadas al AI Agent.
  - Por qué: las tools viven como módulos hermanos en el canvas; un `scenarios_update` las borra silenciosamente.
  - Cómo aplicar: cualquier cambio sobre el agent module (system prompt, threadId, modelo, Input) se hace SIEMPRE desde la UI de Make.
  - **OBSOLETA [2026-05-18]**: la regla original ya no se cumple en el Make AI Agents Beta actual. Ver entrada del 2026-05-18 sobre el roundtrip de validación.
- **2026-04-27** — Campo `Input` del módulo agente = mensaje del usuario; campo `Conversation ID` = threadId.
  - Por qué: confundirlos rompe la memoria del agente.
  - Cómo aplicar: para nuestro caso, Input lleva `[Cliente WhatsApp: {{3.wa_from}}]\n{{3.wa_text}}` y Conversation ID lleva `{{3.wa_from}}`.
- **2026-04-27** — Linked records en Airtable se mandan como array de IDs.
  - Por qué: campos `multipleRecordLinks` rechazan strings sueltas.
  - Cómo aplicar: en el body POST/PATCH usar `"Vendedor": ["{{1.vendedor_record_id}}"]` y similares.
- **2026-04-27** — Acentos en imperativos enclíticos marcan tuteo neutro.
  - Por qué: `gpt-4o` casi resolvió el voseo, pero "confirmame" sin tilde sigue ambiguo. La forma tuteoada lleva tilde: "confírmame", "mándame", "avísame", "pásame".
  - Cómo aplicar: regla específica en el system prompt cura el último 5% del bias regional.
- **2026-04-27** — Cuando una tool funciona y otra no, comparar blueprints completos en JSON crudo antes de hipotetizar.
  - Por qué: la UI puede renderizar idéntico, pero metadata diferente persiste y causa fallos silenciosos.
  - Cómo aplicar: usar `scenarios_get` y `diff` antes de iterar a ciegas.
- **2026-04-29** — Para `http:MakeRequest` con método GET, `contentType` debe ir como string vacío `""`, no como `"json"`.
  - Por qué: setear `"json"` en un GET dispara `BundleValidationError: Validation failed for 1 parameter(s)` aunque el resto del módulo esté correcto. Las versiones que funcionan (`buscar_vendedor`) tienen `contentType: ""`.
  - Cómo aplicar: cualquier nuevo módulo HTTP GET debe tener `contentType: ""`. Reservar `"json"` solo para POST/PATCH con `inputMethod: "jsonString"`.
- **2026-04-29** — Inyectar fields `multilineText` de Airtable directamente en `jsonStringBodyContent` rompe el JSON con `InvalidConfigurationError: The provided JSON body content is not valid JSON`.
  - Por qué: los newlines reales (`\n` literal) dentro de un string JSON no son válidos sin escape; el parser de Make rechaza el body antes de hacer el HTTP.
  - Cómo aplicar: SIEMPRE envolver con `replace(<field>; newline; ", ")` (o cualquier separador inocuo) cuando se incluye un multilineText en un body JSON. Pattern de `buscar_vendedor` (` | ` como separator) es la referencia.
- **2026-04-29** — Aun con `replace(...; newline; ", ")` el body con `Cuenta bancaria` siguió rompiendo: el problema todavía no aislado del todo.
  - Por qué: hipótesis abierta — puede ser que `formatDate(...; "DD/MM/YYYY")` no esté escapando bien las comillas de su segundo argumento dentro del jsonString, o que haya otro campo con caracteres problemáticos.
  - Cómo aplicar: cuando se afine el body completo, agregar componentes de a uno (Nombre cliente → feria → fecha → lugar → ref → monto → cuenta bancaria) y testear cada paso. Aislar cuál rompe.
- **2026-04-29 [CRÍTICO, repetido múltiples veces]** — JC requiere **tuteo neutro estricto** en mis respuestas. NUNCA voseo ni argentinismos.
  - Por qué: JC vive en Ecuador, atiende clientes ecuatorianos. El voseo ("decime", "mandame", "recordá", "avisame", "querés", "linkeás", "dale" como muletilla) le suena ajeno y le ha tocado corregirme repetidamente.
  - Cómo aplicar: usar SOLO formas tuteoadas con tilde correcta — "dime", "mándame", "recuerda", "avísame", "quieres", "enlazas", "ok"/"de acuerdo". Imperativos enclíticos siempre con tilde: "confírmame", "pásame", "fíjate". También evitar "linkear" (preferir "enlazar"). Aplicar igual de estricto a chats conmigo que al bot.
- **2026-04-29** — WhatsApp Cloud API: respuesta `200 OK` con `wamid` NO garantiza entrega real al cliente.
  - Por qué: si el cliente está fuera de la ventana de 24 horas (no le ha mandado mensaje al bot recientemente), el envío `type:"text"` o `type:"document"` free-form es aceptado por Meta pero el mensaje no se entrega. Solo los templates HSM aprobados se entregan fuera de ventana. Esto pasó hoy: el test de `tool_enviar_contrato` devolvió status 1 con dos `wamid`, pero al teléfono de JC no llegó nada.
  - Cómo aplicar: para validar que un mensaje llega de verdad, primero el cliente tiene que escribir al bot (abrir ventana 24h). Para flujos proactivos (recordatorios, confirmaciones fuera de ventana), sí o sí se necesita template HSM aprobado.
- **2026-04-29** — Convención de formato para fields multilineText que se inyectan en bodies JSON: guardarlos en una sola línea con separadores ` | ` desde Airtable.
  - Por qué: la función `replace(...; newline; ", ")` no se resuelve correctamente dentro de `jsonStringBodyContent` (rompe el JSON con `InvalidConfigurationError`), aunque sí funciona en otros mappers como el de `ReturnData`. Es un bug específico del contexto. Reformatear el dato evita el problema sin agregar módulos al flow.
  - Cómo aplicar: el field `Cuenta bancaria` en Ferias se guarda con `|` como separador en una sola línea. Se aplicó al record de Cumbayá (recoTZs473y4CpXvz) el 2026-04-29. Si en el futuro hay que mostrar datos con saltos de línea reales, alternativas: (a) `util:SetVariable` que pre-procese fuera del jsonString, (b) `bodyType:"raw"` en el HTTP module.

- **2026-04-29** — `executions_get-detail` de Make MCP devuelve solo `{"status":"SUCCESS"}` sin payload del execution.
  - Por qué: el endpoint MCP no expone el bundle data como la UI sí lo hace.
  - Cómo aplicar: cuando se necesite leer datos concretos de un execution (ej. `messages[0].image.id` que llegó por webhook), no usar la API MCP — pedir a JC que copie el dato desde la UI de Make (clickeando en el módulo del execution).
- **2026-05-05** — Escapes en `jsonStringBodyContent`: usar UN solo nivel `\"valor\"` para defaults string en `ifempty`.
  - Por qué: el blueprint API JSON-decodifica una vez, y luego Make procesa el mapper. Doble escape `\\\"\\\"` deja `\"\"` literal en el mapper y rompe el body con `InvalidConfigurationError`. Pasamos casi una hora debugging este bug.
